# 本地打印任务恢复系统 - 操作说明

## 一、系统概述

本工具是一个**纯本地运行、不依赖真实打印机**的打印队列模拟与恢复系统。通过模拟打印引擎完整复现打印队列的行为，可用于：
- 柜台打印任务的批量导入与优先级调度
- 打印失败后的自动重试与恢复策略验证
- 需人工处理场景的演练
- 历史记录导出与审计

### 技术栈
- **前端**：Python 3.8+ / Tkinter (ttk)
- **数据层**：JSON 本地持久化（无需数据库）
- **目录**：
  ```
  lfc-00027/
  ├── main.py                  # 程序入口
  ├── core/                    # 核心业务逻辑
  │   ├── models.py            # 数据模型（任务/状态/配置）
  │   ├── storage.py           # 持久化存储
  │   ├── importer.py          # 任务导入与校验
  │   ├── preflight.py         # 预检流程（分组/冲突/确认/导出）
  │   ├── printer.py           # 模拟打印引擎
  │   ├── queue_manager.py     # 队列调度与操作
  │   └── exporter.py          # 历史导出
  ├── ui/app.py                # GUI 界面
  ├── data/                    # 运行数据（自动生成）
  │   ├── tasks.json           # 队列任务
  │   ├── config.json          # 系统配置
  │   ├── export_log.json      # 导出记录
  │   ├── preflight_summaries.json    # 最近预检摘要（重启恢复）
  │   └── preflight_apply_logs.json   # 预检确认入队的操作日志
  └── examples/                # 示例任务文件
      ├── sample_tasks.csv
      └── sample_tasks.json
  ```

## 二、启动与运行

### 系统要求
- Windows 10 / 11（PowerShell 5）
- Python 3.8 及以上（Tkinter 为标准库，无需额外安装）

### 启动命令
在项目根目录下执行：
```powershell
python main.py
```

首次启动时，`data/` 目录会自动创建。关闭窗口后所有状态自动保存，下次打开**完整恢复**（包括队列顺序、重试次数、暂停状态、失败原因、操作者、导出记录）。

## 三、界面结构

### 1. 顶部工具栏
| 按钮 | 作用 |
|---|---|
| 📂 导入任务 | 批量导入 CSV/JSON 格式任务文件（先预检，确认后再入队） |
| ⏸ 暂停 | 对选中任务标记暂停（不参与调度） |
| ▶ 继续 | 对选中的暂停任务恢复调度 |
| 🔄 重试 | 将选中的失败/人工处理任务重新排入等待队列 |
| ✖ 取消 | 取消选中任务（可通过撤销取消恢复） |
| ↩ 撤销取消 | 将已取消任务恢复为等待中 |
| ✓ 人工完成 | 将"需人工处理"任务直接标记为完成 |
| ⏸ 全局暂停 / ▶ 全局继续 | 暂停/恢复整个调度器，不影响单个任务暂停标记 |
| 📤 导出历史 | 导出已完成 + 已取消任务（CSV / JSON） |
| 📤 导出全部 | 导出全部任务 |
| 📋 导出预检日志 | 导出所有预检确认入队的操作日志（JSON） |
| 🗑 清除已完成 | 删除所有已完成/已取消的历史记录 |
| ⚙ 设置 | 打开系统配置对话框 |
| 右侧 操作者 输入框 | 设置当前操作人，回车生效，所有操作会记录此值 |

### 2. 统计信息栏
彩色卡片实时显示 6 种状态的数量 + 总任务数 + 暂停数。

### 3. Tab 状态标签页
- **全部**：查看所有任务（默认）
- **等待中 / 打印中 / 失败 / 需人工处理 / 已取消 / 已完成**：按状态过滤
- 每个 Tab 中任务按 `优先级 → 柜台优先级 → 创建时间` 自动排序

### 4. 任务列表列说明
| 列 | 说明 |
|---|---|
| 优先级 | 数字越小越优先；任务自带自定义优先级时优先使用，否则取柜台配置值 |
| 文件名 | 待打印文件 |
| 份数 | 打印份数 |
| 柜台 | A/B/C/D 类柜台 |
| 状态 | 6 种状态 |
| 重试/最大 | `已重试次数 / 最大重试次数` |
| 暂停 | ⏸ 表示被暂停 |
| 失败原因 | 最近一次失败的具体原因（模拟卡纸/缺墨/脱机等） |
| 操作者 | 最后操作该任务的人 |
| 更新时间 | 最后修改时间 |

### 5. 右下 操作日志
带时间戳的事件流水，包含导入、状态变更、打印结果等，最多 500 行滚动。

### 6. 左下 任务详情
选中任务后显示完整字段（ID、各时间戳、自定义优先级等），支持多选。

## 四、核心操作流程

### 流程 1：导入任务 → 排序 → 自动打印
1. 点击 **📂 导入任务**，选择 `examples/sample_tasks.csv`
2. 导入完成后弹出汇总弹窗：
   - ✅ 成功导入：字段全部合法的任务
   - ⚠ 跳过记录：部分字段超范围，已用默认值（例如重试次数 21 会降到默认 3）
   - ❌ 失败记录：严重错误，未导入
3. 查看"等待中"Tab，任务已按柜台优先级自动排序
4. 调度器自动挑选下一个非暂停的等待任务 → 标记为**打印中** → 模拟打印完成 → 标记为**已完成**

### 流程 2：模拟失败 → 自动重试 → 人工处理
1. 打开 **⚙ 设置**，勾选"启用模拟失败"，滑块拖到 ~50%，保存
2. 导入或手动创建若干任务
3. 观察日志：部分任务会随机失败，自动进入**失败**状态并计数
4. 点击 **🔄 重试** 将失败任务重新排入队列（也可以在设置里把默认最大重试调高，超过后自动进入人工处理，无需手动）
5. 当某任务 `重试次数 == 最大重试次数` 时，**自动转为需人工处理**（紫色卡片数 +1）
6. 选中需人工处理的任务 → 点击 **✓ 人工完成** → 任务直接变为已完成（也可以双击任务快捷操作）

### 流程 3：任务暂停与继续
1. 在"等待中"选中若干任务 → 点击 **⏸ 暂停**
2. 列表中该任务显示 ⏸ 图标，调度器会跳过它
3. 点击 **▶ 继续** 恢复调度；也可以用 **⏸ 全局暂停** 让整个调度器停住，但不修改单个任务的暂停标记

### 流程 4：取消与撤销取消
1. 任意状态（除已完成/已取消外）→ 点击 **✖ 取消** → 任务进入已取消
2. **注意**：已取消任务不能直接用"继续"，必须使用 **↩ 撤销取消**（这正是本工具特意强调的边界表现）
3. 撤销取消后，任务恢复为"等待中"并重新参与排序

### 流程 5：历史导出
1. 完成若干任务后，点击 **📤 导出历史**（仅导出已完成+已取消）或 **📤 导出全部**
2. 选择导出目录 → 选择 CSV 或 JSON 格式
3. 导出文件命名：`print_历史记录_YYYYMMDD_HHMMSS.csv`
4. 导出记录会写入 `data/export_log.json`，重启后可追溯

## 五、边界情况的明确表现

系统对以下异常场景都有**显性的日志 + 弹窗 + 状态变化**：

### 1. 文件名缺失
- **现象**：导入时该条被标记为 ❌ 失败，不加入队列
- **提示**："文件名为空，缺少打印目标文件"
- **示例**：`examples/sample_tasks.csv` 第 26 行、`sample_tasks.json` 第 16 条

### 2. 份数非法（≤ 0 或 > 9999）
- **现象**：导入时该条被标记为 ❌ 失败，不加入队列
- **提示**："份数非法: 0，必须为正整数" / "份数非法: 100000，单次打印不能超过9999份"
- **边界表现**：份数为 1 和 9999 是合法的（示例文件中有对应条目，可正常导入）
- **示例**：`examples/sample_tasks.csv` 第 29、30、31 行

### 3. 失败超过最大重试次数
- **现象**：任务状态从"失败"自动升级为"需人工处理"，紫色卡片 +1
- **日志**："超过重试次数(3)，需人工处理：xxx 原因：模拟卡纸..."
- **后续**：只能通过"重试"（会再次失败）或"人工完成"推进

### 4. 已取消任务再尝试"继续"
- **现象**：按钮点击无效，日志提示明确原因
- **日志**："继续失败：xxx 已取消，不能直接继续，请先使用'撤销取消'"
- **正确操作**：使用 ↩ 撤销取消 → 再 ▶ 继续（如果它还有暂停标记的话）

### 5. 空队列继续打印
- **现象**：调度器在等待，所有操作按钮对空选择给出**"无选择"提示弹窗**
- **UI 状态**：打印中卡片数为 0，调度器正常轮询但不报错
- **日志**：不会出现"空队列错误"类噪音

### 6. 应用重启一致性
关闭窗口 → 重新 `python main.py`，以下内容与关闭前**完全一致**：
- 任务列表的前后顺序（优先级排序一致）
- 每个任务的重试次数 / 最大重试
- 单个任务的暂停标记、全局暂停状态
- 失败原因的具体文字
- 最后操作者字段
- 导出记录（`data/export_log.json`）

## 六、系统配置详解（⚙ 设置）

| 配置项 | 含义 | 范围 | 默认 |
|---|---|---|---|
| 柜台 A/B/C/D 优先级 | 数字越小越先打印，独立可调 | 1-999 | A=1, B=2, C=3, D=4 |
| 默认最大重试次数 | 新导入任务若未指定 max_retries 时使用此值 | 0-20 | 3（=0 表示失败后直接进人工处理） |
| 单次模拟打印耗时 | 每个任务的打印模拟时长，调大可观察状态切换 | 100-60000 ms | 2000 |
| 启用模拟失败 | 勾选后打印过程随机触发失败 | 开/关 | 关 |
| 模拟失败概率 | 每个任务整体的失败概率（滑块 0-100%） | 0-1.0 | 0 |

**调优建议**：
- 演示时建议打印耗时 500-1000ms，失败概率 30-50%
- 压测"人工处理"链路：失败概率 100%，最大重试 2，导入 10 条任务观察自动流转

## 七、任务文件格式

### CSV 格式
- **编码**：UTF-8 或 UTF-8-BOM（推荐 BOM，Excel 直接打开不乱码）
- **必需列**：`filename`, `copies`, `counter`
- **可选列**：`max_retries`, `priority`
- **counter 取值**（大小写/简称/全称均识别）：
  - `A` / `A类` / `A类柜台`
  - `B` / `B类` / `B类柜台`
  - `C` / `C类` / `C类柜台`
  - `D` / `D类` / `D类柜台`

示例：
```csv
filename,copies,counter,max_retries,priority
财务报表.pdf,5,A类柜台,3,
VIP加急单.pdf,1,B类柜台,3,1
```

### JSON 格式
- 根节点必须是数组，每个元素是对象
- 字段与 CSV 对应：`filename`, `copies`, `counter`, `max_retries`, `priority`
- `copies` 可为数字或字符串（内部自动转换）

示例：
```json
[
  {"filename": "合同.pdf", "copies": 3, "counter": "A", "priority": 1}
]
```

## 八、常见问题

**Q：关闭窗口后数据在哪？**
A：`data/tasks.json`、`data/config.json`、`data/export_log.json`，可直接用文本编辑器查看或备份。

**Q：如何彻底重置系统？**
A：删除整个 `data/` 目录，下一次启动会从零开始。

**Q：为什么已经重试的任务还是失败？**
A：设置里的模拟失败开关开启了，进入 ⚙ 设置关掉或把概率调到 0 即可全部成功。

**Q：如何让任务按我指定的顺序优先？**
A：两种方式：① 在设置里调柜台优先级；② 在导入文件里给任务加 `priority` 字段（1 最高），会覆盖柜台配置。

**Q：打印中任务能不能强制完成？**
A：不提供"强制跳过"按钮以保持流程严谨。正确的做法是：取消该任务 → 撤销取消（回到等待队首）→ 关掉模拟失败 → 让它自然成功。
